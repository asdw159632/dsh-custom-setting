## 关于"等长写回"：已论证不可行（round 2）

原目标是"补丁必须恰好 200124 字节、只覆盖那一个条目"，那样**完全不用碰 asar 头部**，也
就不会有这次事故。实测与计算结论：**不可行**。

- 补丁相对官方文件净增 **4604 字节**；
- 去掉注入代码的行首缩进（`tmp\compact_patch.mjs`，安全做法，不动 ASI 语义）
  大约只能回收 **400 字节量级**；
- 缺口仍在 4KB 以上，除非砍功能。

所以**唯一可行路线是"重排式写回"**（数据区整体位移、头部 JSON 长度不变）。
关键是把头部处理做对，而这已经修进 `tmp\write_back_asar.mjs`：

1. **原样保留原头部 16 字节**，只替换 JSON 内容（事故根因就是自己编造了 `u4/u8/u12`）；
2. JSON 长度**恰好等于**原 `jsonSize`，不够用**空格**补齐（**绝不用 NUL**）；
3. 写前三重断言：`u4 === u12+8`、`u8 === 4`、`JSON.parse` 通过；
4. **apply 前整份备份**；
5. `integrity` 只对目标条目重算，其余保持原值；
6. 写后做**独立语义核对**（不复用写入时的假设）。

## 2. 坏在哪（已定位到具体字节）

asar 头部是 `8~16 字节字段 + JSON`。官方文件里 JSON 长度 = `3392048`，我读到的字段是：

| 字段 | 值 | 我的理解 |
| --- | --- | --- |
| u4 @0 | 4 | 版本/魔数 |
| u8 @4 | 3392056 | = J + 8 |
| u12 @8 | 3392052 | = J + 4 |
| u16 @12 | **3392048 (J)** | **JSON 真实长度** |

我原来的读取器用 `u16` 当长度、JSON 从字节 **16** 开始读 —— 这个组合**成功解析出了全部 12967 个条目**，
所以它是对的。

但我的写回器在写头部时，把 JSON 写到了字节 16、同时把长度字段写成了 `u8=jsonSize`、`u12=newJsonSize`，
**没有保持原文件的 `u8=J+8 / u12=J+4` 关系**。也就是说：我改变了头部字段的语义，
而 node-asar 里的读取逻辑可能与我的不同 → 它可能从字节 8 开始读、读到错误长度 → `JSON.parse` 失败。

**我无法在我这边验证这一点**，因为我的命令通道在写回之后就彻底坏了
（`subprocess-local: Windows Job runner exited with exit code 1 before proving its managed range empty`；
pwsh / grep / read 工具全部失败）。

### 方案 B（结构恢复）：把头部字段还原 + 数据区前移 8 字节

依据：**当前文件里 offset ≥ 16 的字节与官方原文件逐字节相同，只是偏移了 +8**。
这是真的，因为写回器只做了两件事：把目标条目换成长 204728 的补丁，
以及**在 JSON 区尾部多了 8 字节**（16+J+8 = 24+J 才是数据区起点）。

所以恢复 = 「还原头部 16 字节的原始值」+「让数据区回到 `16+J`」。

`tmp\restore-asar-below-J.mjs` 实现的就是这个：

```js
// 绝对路径：D:\文档\DSH-plugin\DSH-custom\tmp\restore-asar-below-J.mjs
```

1. 写回字节 4 与 12 的原始值：`0x0033C238` 与 `0x0033C230`（即 3392056 / 3392048）；
2. 把 `[16+J+8, EOF)` 的数据整段前移 8 字节到 `16+J`；

## 6. 下次打补丁前必须修的写回器缺陷（builder-verify 已指出）

1. 头部字段：`u8` 与 `u12` 必须保持原文件的关系（实测 `u8=J+8`、`u12=J+4`，`u16=J`），
   JSON 位置/长度必须与这套关系自洽 —— 或干脆**原样保留原头部 12 字节，只替换 JSON 内容**。
2. JSON 尾部填充必须用**空格**，不能用 NUL。
3. `integrity` 不要全量重算成单块：实测 8 个条目是多块（最大 43 块），
   内容未变的条目必须保持原 integrity。
4. apply 前必须先整份备份 `app.asar`。
5. 自检不能复用与写入相同的头部假设（那样永远发现不了头部错误）——
   必须用一个独立读取器或官方的解析实现来验。
